FUSH ERP Mobile v212 — Shipment Number Collision Hotfix
========================================================

Release identity
- applicationId: com.fush.erp.recovery
- versionCode: 212
- versionName: 0.15.4.163-shipment-number-collision-hotfix
- Room schema: 53 (unchanged from v211)
- Destructive migration: NOT used

Root cause fixed
- A cloud-hydrated shipment can advance sales_shipments without advancing the secondary phone's local DOC:SHP:<date> number_sequences row.
- The accountant phone could therefore generate an SHP number that already existed locally and hit:
  UNIQUE constraint failed: sales_shipments.shipmentNo

v212 fix
- ShipmentDao exposes the highest persisted automatic SHP suffix for a business-date prefix.
- AutoNumberService.nextShipmentNo() reconciles local number_sequences against persisted/hydrated shipment rows before allocation and skips any existing candidate.
- Connected shipment creation reserves SALE_SHIPMENT numbers through the company-wide document-number guard before local insert.
- Existing cloud shipment numbers were backfilled into fush_document_number_registry.
- A Supabase trigger automatically registers future synced SHIPMENT numbers, including shipments coming from older app versions.
- fush_reserve_document_number rejects SALE_SHIPMENT numbers already represented in cloud sales auxiliary documents.
