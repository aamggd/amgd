FUSH ERP Mobile v203 — Room 49→50 Startup Migration Hotfix
===========================================================

Root cause fixed
----------------
FushErpApplication opens the production database first through
AccountingWaveBRoomBootstrap.migrateBeforeContainer(). In v202 that bootstrap
registered migrations only through 48→49. AppContainer did contain 49→50, but
startup failed before AppContainer could be created.

Fix
---
- Added MIGRATION_49_50_LOCAL_FX_ENGINE to AccountingWaveBRoomBootstrap.
- Added contract test to require 48→49 followed by 49→50 in the startup bootstrap.
- Room schema remains 50. No 50→51 migration is required.
- No fallbackToDestructiveMigration, deleteDatabase, or clearAllTables in production source.
- User data is preserved.
