# FUSH ERP Mobile — Accounting Branch

هذا المجلد مخصص حصريًا لتعديلات الحسابات على الفرع `fush/accounting`، والمرجع الأساسي له هو `fush/main`.

## حدود الفرع
- الحسابات العامة والقيود.
- العملاء والموردون من ناحية الذمم والتسويات المحاسبية.
- الخزائن والبنوك والترحيل النقدي.
- الفترات والإقفالات والمطابقات المحاسبية.
- التقارير والضوابط المحاسبية المرتبطة بهذه التعديلات.

لا تُضاف هنا تعديلات الواجهة الاحترافية العامة أو صلاحيات المستخدمين؛ لها فروع مستقلة.

## ترتيب تطبيق الحزم
يجب تطبيق الحزم بالترتيب التالي فوق المصدر الأساسي الموافق لـ `fush/main`:

1. `patches/phase14.5.34-accounting-integrity.patch.gz.b64`
2. `patches/phase14.5.35-accounting-periods-reconciliation.patch.gz.b64`
3. `patches/phase14.5.36-operational-reversals.patch.gz.b64`
4. `patches/phase14.5.37-fiscal-year-closing.patch.gz.b64`
5. `patches/phase14.5.38-treasury-bank-reconciliation.patch.gz.b64`

## فك الحزمة وتطبيقها
مثال Linux/macOS:

```bash
base64 -d patches/phase14.5.34-accounting-integrity.patch.gz.b64 | gzip -d > phase14.5.34.patch
git apply phase14.5.34.patch

base64 -d patches/phase14.5.35-accounting-periods-reconciliation.patch.gz.b64 | gzip -d > phase14.5.35.patch
git apply phase14.5.35.patch

base64 -d patches/phase14.5.36-operational-reversals.patch.gz.b64 | gzip -d > phase14.5.36.patch

base64 -d patches/phase14.5.37-fiscal-year-closing.patch.gz.b64 | gzip -d > phase14.5.37.patch
git apply phase14.5.37.patch

base64 -d patches/phase14.5.38-treasury-bank-reconciliation.patch.gz.b64 | gzip -d > phase14.5.38.patch
git apply phase14.5.38.patch
```

## Phase 14.5.34 — Accounting Integrity
- حماية حسابات الرقابة من القيد اليدوي المباشر.
- تسويات العملاء والموردين مرتبطة بالفاتورة.
- إصلاح فروق العملة لتحصيل العملاء.
- اختيار الخزينة/البنك الفعلي بدل الحساب النقدي الثابت.
- منع اختلاف عملة الخزينة عن عملة العملية.
- تصحيح تواريخ قيود عمولات المندوب.

## Phase 14.5.35 — Accounting Period Control & Reconciliation
- Schema 28 مع `accounting_periods`.
- 12 فترة شهرية للسنة المالية.
- إقفال وإعادة فتح الفترات مع سجل تدقيق.
- Trigger على مستوى SQLite يمنع أي قيد بتاريخ داخل فترة مقفلة.
- مطابقة `1300 العملاء` مع سجل العملاء.
- مطابقة `2100 الموردين` مع سجل الموردين.
- مطابقة `1200 المخزون` مع تقييم حركات المخزون.
- فحص فرق ميزان المراجعة.
- منع إقفال الفترة إذا كانت المطابقات غير سليمة ضمن سماحية 0.01 من العملة الأساسية.

## Phase 14.5.36 — Operational Reversals
- Schema 29.
- عكس موثق لتحصيلات الفواتير الآجلة دون حذف المستند الأصلي.
- إعادة فتح ذمة الفاتورة تلقائيًا عبر تخصيص عكسي.
- عكس القيد الأصلي نفسه، بما فيه الخزينة وفروق العملة.
- إعادة احتساب عمولة المندوب بعد عكس التحصيل.
- عكس دفعات الموردين وإعادة رصيد الفاتورة المستحق.
- منع العكس المكرر والعكس داخل فترة محاسبية مقفلة.
- إظهار مستند العكس في ملف العميل والمورد وكشف الحساب وسجل التدقيق.

## Phase 14.5.37 — Fiscal Year Closing
- Schema 30 وجدول سجل دورات الإقفال السنوي.
- الفترة 12 لا تُقفل منفردة؛ تُقفل من الإقفال السنوي فقط.
- الإقفال السنوي يتطلب إقفال الفترات 1–11 ونجاح المطابقات.
- تصفير حسابات الإيرادات والمصروفات وترحيل صافي الربح/الخسارة إلى `3300 الأرباح المحتجزة`.
- قائمة الدخل تستبعد قيد الإقفال وعكسه حتى يبقى ربح السنة التاريخي ظاهرًا بصورة صحيحة.
- إعادة فتح السنة تفتح الفترة 12 وتعكس قيد الإقفال الأصلي بالكامل مع الاحتفاظ بسجل التدقيق.
- منع إعادة فتح سنة أقدم إذا توجد فترات أو سنوات لاحقة مقفلة.

## Phase 14.5.38 — Treasury & Bank Reconciliation
- Schema 31.
- جرد فعلي للصندوق يقارن الرصيد الدفتري بالموجود النقدي.
- فرق الجرد يبقى موثقًا ولا يسمح بإقفال الفترة قبل تسويته.
- تسوية فرق الصندوق تمر بقيد `CASH_COUNT_ADJUSTMENT` عبر الحساب `6950 — فروقات الصندوق` مع سبب ومستخدم وسجل تدقيق.
- كشوف بنكية بفترات غير متداخلة وحركات موجبة للإيداع وسالبة للسحب.
- كل حركة كشف بنكي ترتبط بالقيد الدفتري المقابل على حساب البنك نفسه.
- الحركات الدفترية غير الظاهرة في الكشف تبقى Outstanding وتدخل في الرصيد البنكي المعدل.
- اعتماد المطابقة يتطلب صحة معادلة الكشف، مطابقة جميع حركاته، وتطابق الرصيد البنكي المعدل مع الأستاذ ضمن 0.01.
- إقفال الفترة يتطلب جرد الصندوق في اليوم الأخير وعدم وجود فرق غير مسوّى، وكشفًا بنكيًا `RECONCILED` يغطي الفترة لكل بنك عليه حركة.
- العملات الأجنبية تُمنع من اعتماد الإقفال بهذه الآلية حتى إضافة دفتر العملة الأصلية وإعادة التقييم، بدل إعطاء مطابقة غير صحيحة.

## ملاحظات الدمج
عند الدمج في `fush/main` يجب الحفاظ على ترتيب المراحل. أي تعارض مع فرع الواجهات أو فرع الصلاحيات يجب حله على مستوى التكامل دون إسقاط منطق سلامة الحسابات.
