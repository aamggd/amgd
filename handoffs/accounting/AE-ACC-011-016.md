# Accounting Handoff — AE-ACC-011 / AE-ACC-016

- Defect IDs: AE-ACC-011, AE-ACC-016
- Root Cause: Journal lines had only functional debit/credit and memo; transaction-currency semantics and analytical dimensions were not persistable, and dimension reports had no explicit balancing policy.
- Fix: Added a 1:1 `journal_line_semantics` record for every journal line. Functional debit/credit remain canonical in `journal_lines`; semantic rows carry transaction currency/amount/rate, line number, branch, cost center, project, party and source reference. A database trigger auto-creates a semantic row for every new journal line. `AccountingJournalLineSemantics` explicitly balances only functional amounts and distinguishes NON_BALANCING vs BALANCING dimension policies.
- Historical Backfill: Existing rows are preserved and receive semantic rows with `transactionCurrencyCode=FUNCTIONAL`, transaction amounts equal to functional amounts and rate=1.0 because original per-line transaction amounts cannot be reconstructed safely from historical functional-only storage.
- Database Impact: Room 36 -> 37 through explicit non-destructive `MIGRATION_36_37_JOURNAL_LINE_SEMANTICS`; no existing table/row is dropped or recreated.
- Tests: mixed transaction currencies balance on functional amounts; functional imbalance rejection; non-balancing dimensions allowed without claiming balance; balancing dimension requires per-key functional balance; SQLite migration harness verifies IDs/counts/backfill.
- Known Integration Contract: New posting paths that possess original transaction amounts should overwrite the default FUNCTIONAL semantic row with exact transaction currency/rate/amount. Historical values remain functional-only by design rather than being guessed.
- Status: FIXED / READY FOR PRE-INTEGRATION QA; Android migration/build validation required.
